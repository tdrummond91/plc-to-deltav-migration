  1. Under Programs & routines, choose a familiar routine. Select a rung's title to open it; its checkbox is for bulk edits.

03

MAKE A STRUCTURED CHANGE

Recategorize, group, and save

Review a rung ↗Open engineering groups ↗
  1. In the rung detail, find Your engineering review. Choose one or more categories. Use Manage categories if you need another label.
  2. Set Needs review while uncertain, or Confirmed after checking. Enter an engineering property such as Purpose, PV, SP, Output, or Equation. Select Save review.
  3. Select Add this source to a group, or check individual instruction boxes and select Group checked instructions. Name the engineering group and save it.

Use the right scope: a saved classification changes that source's reviewed interpretation. A reusable category rule proposes labels for other rungs with the same opcode and branch pattern; it never approves them. Group membership supports several rungs per object and several groups per rung.

04

CHECK THAT YOUR WORK SURVIVES

Reopen your decision and back up

Open changes & reconciliation ↗
  1. Select another rung and return to the one you edited. Reload the page and open that rung again. Verify that your reviewed categories and properties remain.
  2. Open Changes & reconciliation to inspect the recorded change. Undo latest change reverses the latest eligible edit while retaining its history.
  3. Select Back up project in the top bar. Keep that database backup with your original source exports and saved analysis runs in your private project location.

When you rerun analysis: the usual work-check command updates the same project with its completed result. Prior decisions remain recorded. Changed source or changed evidence is flagged for review; explicit correspondence reconnects a prior decision to a new source record.

How DeltaV classes fit later

A source group can map to several target classes, and several source fragments can contribute to one target object. A loop might fit AI_PID_AO, or AI_PID with intermediate classes and an _AO output. Class alarms, equations, and multiple or nested timers may require different categories or split implementations. Use groups and structured properties to retain those decisions. The workspace does not yet generate or certify those target designs.
