## Private evidence

Execution context1 contains seven groups:

- Tasks: original attributes, event information and captured schedule references.
- Programs: original attributes, schedule references and main/fault designations.
- Schedules: source order, owning task, lexical program candidates and qualification.
- Designations: separate main/fault attributes, including absent and empty values.
- Routine calls: each JSR occurrence, target candidates, incoming condition DAG,
  branch/stateful context, and original argument fields.
- Control boundaries: each SBR/RET/JMP/LBL occurrence and incoming conditions;
  static label candidates stay within one routine and one exact content container.
- Routines: captured body status, incoming/outgoing calls, designations and controls.

Metadata stays as original text. No time-unit conversion, effective task order,
execution simulation, input/output parameter split, type validation or active
edit selection is inferred. A source schedule link does not prove execution.
Multiple callers do not become a synthesized routine-enable expression.
Other edit candidates are visible separately and do not settle label matching.

Namespace qualification covers the source ancestry and guard binding dependencies,
including aliases and implicit module metadata. Unknown attributes in foreign
namespaces remain gaps. Incoming guards follow actual DAG children, preserving
sibling independence. A call's own opaque transfer does not contaminate its
incoming condition; an earlier opaque transfer remains visible.

The declaration model follows the program/task sections of Rockwell's
[Logix 5000 import/export reference](https://literature.rockwellautomation.com/idc/groups/literature/documents/rm/1756-rm014_-en-p.pdf).
The distinction between call, entry and return instructions is documented in
[Rockwell's JSR/SBR/RET help](https://www.rockwellautomation.com/en-us/docs/studio-5000-logix-designer/38-00/contents-ditamap/instruction-set/program-control-instructions/jump-to-subroutine--jsr---subroutine--sbr---and-re.html).
The implementation retains lexical fields because the source alone does not
establish a safe parameter-role interpretation for every captured RLL form.
