## Private evidence

`SfcContextResult` authenticates the relationship, SFR and SFC-condition chains
before producing four bounded collections:

| Collection | Evidence retained |
| --- | --- |
| References | One record per parsed reference occurrence, its original condition, scope, content/edit, qualification, shared address and optional diagnostic. |
| Addresses | One shared group per qualified declaration ID and exact expanded suffix, with accepted and excluded RLL operand/expression uses. |
| Step links | Bound-identity candidates or explicitly lexical hints, including source step, content, routine, edit relation and namespace qualification. |
| Gaps | Source-root versus alias-chain gaps, spelling category, failing lookup scope/root and outside-scope declaration or lexical step candidates. |

Reader/writer lists are stored once per address; repeated transition references
do not duplicate those lists or create writer-by-consumer pairs. Each explicit
operand keeps its existing read, write, read/write or unknown role. CPT leaves
remain separate expression readers. The report counts distinct captured writer
instructions, not operand slots, and separately displays excluded occurrences.
Step candidates are indexed by exact target/suffix and looked up through literal
member delimiters. Unrelated steps on a shared array root are not rescanned for
every reference; matching candidates retain their original source order.

RLL uses retain the established semantic-attribute and ancestor qualification
policy. SFC bindings additionally use their existing conservative attribute
qualification; both account for the ports and parent-module dependencies used
by inferred module I/O names. Explicit names retain their declaration ancestry.
Qualification cannot validate physical I/O channels or runtime values.

Step candidates require an identical resolved declaration and either an exact
suffix or a suffix followed by a literal member delimiter. Suffix case, index
spelling and whitespace remain exact: `[0]` is not merged with `[00]`. A whole
array does not imply a particular indexed step. Nested member candidates are
lexical; no STEP data type or member behavior is validated. Same-content,
other-edit and peer-chart associations remain separate. Matching controller
declarations can connect different programs; local shadow declarations do not.

For a missing alias target, diagnostics inspect the last alias's lookup root
and declaration scope. Another program's matching declaration is a hint, never
a promoted binding. Same-scope Step `Operand` spelling can provide a lexical
hint even when no declaration binds. `TRUE`/`FALSE` is only a closed spelling
category; no Boolean constant value is inferred. Earlier unresolved records
are preserved.

## Review navigation

The existing **Sequence conditions** view gains a relationship summary and a
binding-diagnostics filter. Open a transition, then **Ladder and chart
relationships**, to inspect a reference. Its detail shows qualified/excluded
ladder uses, step candidates, edit provenance and diagnostic declaration links.
The shared address page lists every captured sequence reference with pagination.
Transition details also expose direct chart connections and note attachments
from the existing structural model. These do not perform graph traversal or
infer sequence execution. Source strings are inserted as text.
