Operate → Live · guided exercise

Build it. Click it.
Follow the connection.

A checkbox walkthrough for opening the right applications, building a custom popup, passing module context, creating a reusable GEM, and testing read-only data.

Process display→GEM / button→Contextual popup→Detail + module data
Scope of the exercise

Use the core workflow on one identified v15 or v16 system first. v14, installed libraries, feature packs and licensing can differ. Placeholder names are examples, not existing module names. The first pass creates graphics only; controller reads and publication are later, explicit stages.

Phase 01

Choose the station and establish the starting point

Use one v15 or v16 training/engineering environment for the first pass. These steps use core features described in the reviewed help; they are not a version-by-version certification. Check the installed release’s help when labels differ. v14 follows the same conceptual map, with its own installed-version and licensing checks.

Windows / site system information

Identify the DeltaV release and feature pack, workstation, and whether the connection is to a training/test or operating system. An engineering workstation can still be connected to an operating plant.
Expected result
The system and station are identified before configuration work begins.
DeltaV / Operate connection
The workstation is the host. Graphics Studio edits graphics configuration; the controller runs control modules. These are separate roles.

DeltaV engineering workstation

Use a workstation where Graphics Studio is already installed, licensed and able to connect to the site graphics configuration database. Sign in with an account permitted to create training graphics. If it is missing or access is denied, have the site administrator identify the appropriate station/account; this exercise does not install DeltaV or change account permissions.
Expected result
Graphics Studio can be opened and the intended graphics database is accessible.
DeltaV / Operate connection
This is the Live graphics engineering environment, corresponding to the graphics work you performed in Operate Configure. It is not Control Studio.

Graphics Studio

Use the names TRAIN_CONNECTIONS, TRAIN_PUMP_POPUP, TRAIN_PUMP_DETAIL and TRAIN_PUMP_TILE only if they are unused. Otherwise add a unique suffix consistently. Use a designated training area/library. On a production-connected system, use the site-approved place for training work; do not modify an existing operating display or standard class.
Expected result
The exercise will create its own objects rather than replace existing ones.
DeltaV / Operate connection
A saved graphic is configuration. Saving into a shared database is distinct from publishing it to operator runtime.

Graphics Studio / Quick Online View

The first pass uses only new buttons and labels. Add real module data later as read-only. Quick Online View tests graphics before publication; do not treat it as a guaranteed disconnected controller simulator. Do not add Start/Stop, Setpoint, Write Value or SIS-write actions for this exercise.
Expected result
You can demonstrate opening windows and passing context without commanding equipment.
DeltaV / Operate connection
An HMI action may reach a real DeltaV parameter. The fact that a display is being tested does not establish that its data source is simulated.

Phase 02

Open the applications and learn the workspace

Open Graphics Studio first. Use the other applications for their specific roles; a new graphics exercise does not require creating or switching a Live database.

Windows → Graphics Studio

Open Windows Start, search for Graphics Studio, and launch the installed DeltaV application. In installations organized by Start-menu folders, look under DeltaV Engineering. Allow the existing site configuration to load. If it cannot connect, use the exact error message to troubleshoot the connection rather than creating or switching databases.
Expected result
A ribbon, Explorer panes and a central editing area appear.
DeltaV / Operate connection
Graphics Studio is the display authoring application. DeltaV Live is the runtime application, comparable to the Configure/Run distinction in Operate.

Graphics Studio

Find Graphics Explorer and Library Explorer. They may share a docked location with tabs. If a pane is hidden, use the View tab and the pane controls. Graphics Explorer contains Displays, Contextual Displays, Display Sets and Layouts. Library Explorer contains libraries with GEM Classes, Templates, Standards and Functions.
Expected result
You can switch between the graphics hierarchy and the reusable-library hierarchy.
DeltaV / Operate connection
A process picture or popup belongs in Graphics Explorer. A reusable dynamo-like definition belongs in the GEM Classes library.

Graphics Studio

Find the central document tabs/canvas, the Palette, the Selection pane and the Graphics Configuration pane. The Selection pane lists contained elements. The Graphics Configuration pane changes depending on what is selected. Select the display root when changing the display; select a child shape when changing that shape.
Expected result
You can identify which object owns the properties currently being edited.
DeltaV / Operate connection
A display contains objects, and a GEM can contain more objects. Editing the outer container and editing a nested element are different operations, as with a picture and a dynamo component in Operate.

Windows / installed DeltaV applications

Locate DeltaV Explorer and Control Studio for the later read-only parameter check. Locate DeltaV Live for runtime. Locate DeltaV Live Administration only to understand where workstation/session assignments and configuration-server management live; no database creation, switch or workstation reassignment is needed here.
Expected result
You know which application to open for graphics, control logic, runtime and administration.
DeltaV / Operate connection
DeltaV Explorer organizes system/modules; Control Studio shows module logic; Graphics Studio builds the HMI; Live runs it; Live Administration manages the Live environment.
Help topics: DeltaV Live Administration overview Graphics Studio overview The Graphics Studio user interface The Graphics Studio ribbon
Phase 03

Create the main process display

This is the parent screen that will contain the two pump buttons, then two instances of the reusable GEM.

Graphics Studio → Graphics Explorer

Select Graphics Explorer. On Home, in the Graphics group, choose New → Display → Blank Display. Rename the new item in the Explorer tree to TRAIN_CONNECTIONS using its Rename command. If that name was already used, apply your chosen suffix.
Expected result
A blank process display opens as a document tab and appears under Displays.
DeltaV / Operate connection
This is the Live counterpart of the saved process picture (.grf), not a GEM class or a popup.

Graphics Studio → Palette / drawing tools

Add a Text element to the display. Select it, open its Text tab and set Label to Training: display to popup connections. Resize the text element so the whole label is visible. The Basics → Title field is an engineering name, not necessarily visible runtime text.
Expected result
The heading appears on the canvas.
DeltaV / Operate connection
Visible text belongs to an element. Engineering titles help locate the element in the Selection pane but do not replace its displayed label.

Graphics Studio

Click Save. Keep the display open; you will return to it after building the popup.
Expected result
TRAIN_CONNECTIONS is saved and remains available in Graphics Explorer.
DeltaV / Operate connection
Save stores authoring configuration. It does not by itself make the new display available to all running operator stations.
Help topics: Create a display Text: Configurable properties (Text tab)
Phase 04

Build the custom popup

This first popup is the simplest replacement for the presentation part of an Operate VBA UserForm. It will show the tag/context that the caller passes.

Graphics Studio → Graphics Explorer

With Graphics Explorer active, choose Home → New → Contextual Display → Blank Contextual Display. Rename it TRAIN_PUMP_POPUP. Select the contextual display root rather than a child element.
Expected result
A separate contextual display document appears under Contextual Displays.
DeltaV / Operate connection
A UserForm is a VBA form object in Operate. In this Live exercise, a contextual display provides the popup window and its contained controls.

Graphics Studio → Graphics Configuration → Basics

In Size, choose a compact width and height appropriate to the current measurement unit. Leave Fit to Display Frame unset when specifying your own size. In Information, set Window Title to the expression Dsp.Tag without quotation marks. Leave Contextual Display Type at the untyped -- choice for this first custom popup; typed Faceplate/Detail categories also affect pinning and replacement behavior.
Expected result
The popup has a defined size, and its runtime title will resolve from the tag supplied by its caller.
DeltaV / Operate connection
Dsp refers to this display context. Dsp.Tag is how the contextual display refers to the primary tag passed into it; it is not a hard-coded module name.

Graphics Studio → Text element

Add a Text element. In its Text → Label property enter This popup receives its tag from the clicked button. Add a second label: No control commands are configured. Resize as needed and save.
Expected result
The popup contains visible content and is saved under its own name.
DeltaV / Operate connection
The main display will contain a reference to this popup, not a copy of the popup canvas. Multiple callers can reuse the same contextual display definition.
Help topics: Create a contextual display Contextual display: Configurable properties (Basics tab) Text: Configurable properties (Text tab)
Phase 05

Connect two buttons to the same popup

For the first test, use two valid module tags available on the chosen system. The guide calls them Tag A and Tag B; substitute the actual names when configuring DeltaV. The popup only displays their names; it contains no parameter writes. If no modules are available, defer the real-tag validation rather than claiming fictional names prove a data connection.

Graphics Studio → TRAIN_CONNECTIONS

Return to the main display. Drag a Button from the Palette onto the canvas. Set its visible label/caption to Open Tag A using the button text properties. In the Selection pane give it a useful engineering title if desired.
Expected result
A clickable button is positioned on the process display.
DeltaV / Operate connection
This is equivalent to the Operate button whose click event would call a UserForm or open another picture.

Graphics Studio → Button → Interaction

Select the button. Open Interaction, choose Add Action → Click Action, and select Open Contextual Display. Configure the action once; button click configuration is reflected in its other equivalent property locations. Set Contextual Display to the quoted expression "TRAIN_PUMP_POPUP", adjusted to your actual saved name. Set Tag to the quoted name of Tag A, for example "TRAIN_P101" only if that module actually exists. Leave Optional Contexts unused and set Active to True.
Expected result
The button specifies both which popup to open and which module context to supply.
DeltaV / Operate connection
The display name selects the GUI definition. The Tag selects the equipment/context. These are separate inputs, like opening one reusable Operate form with a module argument.

Graphics Studio → TRAIN_CONNECTIONS

Copy/paste the first button and move it beside the first. Change its caption to Open Tag B. Change only its click action Tag to the quoted Tag B. Keep the same contextual display name. Save the display.
Expected result
Two buttons reference one popup definition while supplying different tags.
DeltaV / Operate connection
You are reusing the popup rather than creating one popup per pump. This is the key connection between a caller and a contextual display.

Graphics Studio → Button → Interaction

Inspect the available behaviors without changing your action: Open Contextual Display explicitly names the popup; Open Faceplate opens the faceplate associated with the specified tag; Open Detail opens its associated detail display. Keep Open Contextual Display for this exercise so it does not depend on changing the module associations.
Expected result
You can explain why these actions are not interchangeable.
DeltaV / Operate connection
A module can have faceplate/detail associations. Selecting an explicit contextual display is a separate route, useful when replacing a custom UserForm or custom popup.
Help topics: Button: Configurable properties (Interaction tab) Contextual display: Configurable properties (Basics tab) Contextual displays overview
Phase 06

Verify and run the first connection

Use Quick Online View before publication. A successful design-time verification and a successful runtime test establish different things.

Graphics Studio → Home → Verify

Select TRAIN_CONNECTIONS, then choose Home → Graphics → Verify. Inspect the Verification Results pane. Open the relevant item from any error row and correct the property. Repeat for TRAIN_PUMP_POPUP. An Information entry is not automatically an error; read its severity and explanation.
Expected result
No unresolved configuration errors remain for the two exercise items.
DeltaV / Operate connection
Verification checks configuration issues. It does not prove that a live module exists, that its value is usable, or that every runtime interaction behaves as intended.

Graphics Studio → Review → Online

Make TRAIN_PUMP_POPUP the active document and use Review → Online → Quick Online View if enabled for that contextual display. Then make TRAIN_CONNECTIONS active and choose Quick Online View. Use Manage Quick Online View to check the queued items. The help describes testing multiple displays together, including opening contextual displays from buttons. If the contextual-display command is unavailable in the installed release, use that release’s help to resolve how the popup is included; do not assume a previously published popup is the new version.
Expected result
The main display runs in the Quick Online View instance and its intended popup configuration is available for the test.
DeltaV / Operate connection
Quick Online View is a Live test instance using queued configuration. It lets you test behavior before the normal publication workflow.

DeltaV Live → Quick Online View

Click Open Tag A. Confirm the popup title is Tag A. Close it, then click Open Tag B and confirm the title is Tag B. Confirm both contain the same explanatory labels. Test sequentially first so pinning/replacement behavior does not obscure which context was used.
Expected result
One popup definition displays the context supplied by each different caller.
DeltaV / Operate connection
The click opens the window; the Tag argument supplies context; Dsp.Tag resolves that context inside the popup. No VBA UserForm host is involved.

Graphics Studio / Quick Online View

Change the popup label to append Revision B, save, and re-add the changed item to Quick Online View. Reopen it from the main display and confirm the label changed. After later changes, also re-add any changed caller display. Saving alone does not update an item already queued for testing.
Expected result
The updated runtime popup visibly shows Revision B.
DeltaV / Operate connection
There are separate saved, queued-for-test and published versions. Confusing these stages can make a correct edit appear ineffective.

Phase 07

Add a detail popup and pass context again

Now demonstrate the second hop: process display → popup → detail. The detail remains an explicitly named contextual display for the exercise.

Graphics Studio → Graphics Explorer

Create another blank contextual display called TRAIN_PUMP_DETAIL. Set its Window Title to Dsp.Tag. Add a Text label reading Training detail: context forwarded by parent popup. Leave it untyped for this initial exercise and save.
Expected result
A second popup definition exists independently of the first.
DeltaV / Operate connection
A detail display is another contextual display; it is not automatically embedded inside the faceplate or the controller module.

Graphics Studio → TRAIN_PUMP_POPUP

Add a Button labeled Details. On its Click Action choose Open Contextual Display. Set Contextual Display to "TRAIN_PUMP_DETAIL". Set Tag to Dsp.Tag without quotes. Save and verify the popup and detail.
Expected result
The action forwards the current popup’s tag, rather than hard-coding Tag A.
DeltaV / Operate connection
Quoted "Dsp.Tag" would be literal text. Unquoted Dsp.Tag is the expression carrying the current module context into the next window.

Graphics Studio / Quick Online View

Refresh the relevant items in Quick Online View. Open Tag A → Details, then repeat for Tag B. Close prior windows between runs. Confirm the detail title matches the module selected on the main display in each case.
Expected result
Both paths preserve their original tag across two window-opening actions.
DeltaV / Operate connection
This is the same responsibility a custom Operate form/picture chain has when passing a module name through several windows.

Phase 08

Turn the caller into a reusable GEM

Build a small button tile as the first GEM. Its purpose is to demonstrate class, instance and configuration properties clearly; pump artwork can be added afterward. Linked-class behavior requires the applicable licensing.

Graphics Studio → Library Explorer

In the designated editable training library, select its GEM Classes folder. Choose Home → New → GEM Class. Name it TRAIN_PUMP_TILE. Add a Button to its canvas and label it Open pump. Save the class.
Expected result
A reusable class appears in the library, separate from the process display.
DeltaV / Operate connection
This is the closest part of the exercise to creating a source dynamo definition in a dynamo set. A GEM class is a Live library item rather than an .fds file.

Graphics Studio → Format / GEM Class Tools

With the class active, choose Format / GEM Class Tools → Configuration Pane → Design. In GEM Configuration Designer, click Add Property Group. Select that group and choose Add Property → Control tag. Set the new property Title to ModuleTag, give it a description such as Module whose popup this instance opens, and select a valid default tag using the provided value/browser control. Keep Presence set to Always Present. Save the design/class.
Expected result
The GEM exposes a module-selection option when placed on a display.
DeltaV / Operate connection
The Configuration Designer defines the options that a display engineer sees, serving a role similar to a dynamo configuration form. It is not a general-purpose runtime UserForm editor.

Graphics Studio → GEM class → internal Button

Return to the GEM canvas. Select its internal button. Configure Click Action → Open Contextual Display and the same TRAIN_PUMP_POPUP name. For Tag, use the diamond/reference picker and choose GEM Configuration Properties → ModuleTag where offered, or Browse for Reference to that property. Let the editor generate the reference; do not enter the literal string "ModuleTag". Verify and save the class.
Expected result
The internal action obtains its module tag from the containing GEM instance’s configuration.
DeltaV / Operate connection
Class behavior stays common. The instance supplies the equipment-specific value. This separates reusable code/behavior from per-pump settings.

Graphics Studio → TRAIN_CONNECTIONS → Palette

Find TRAIN_PUMP_TILE in the Palette under its library/folder. Drag it normally onto TRAIN_CONNECTIONS twice. Do not hold Alt or Shift+Alt: the documented modifiers create unlinked GEMs. Select each placed instance and set its exposed ModuleTag to Tag A or Tag B using the property editor. Use the title/label beside each tile to identify which is which. Save.
Expected result
Two placed tiles use one class and have different ModuleTag values.
DeltaV / Operate connection
A class is the reusable definition; the placed GEM is the instance. The two instances do not require two separately maintained button implementations.

Graphics Studio → placed GEM properties

Confirm the placed items are linked GEMs. The reviewed help says applicable Premium licensing is required for certain linked-GEM creation and engineering operations; without it, placement can produce unlinked GEMs. If you obtain unlinked instances, recognize that they will not track the class. The popup/context exercise still works, but the class-propagation test below will not demonstrate linked behavior.
Expected result
You know whether these instances track their class.
DeltaV / Operate connection
An unlinked GEM is closer to a copied object definition: later class edits do not automatically reach it. This is a real functional distinction, not just an icon difference.

Graphics Studio / Quick Online View

Verify and re-add TRAIN_CONNECTIONS to Quick Online View. Test each tile. Next, edit the button label in TRAIN_PUMP_TILE to Open pump information and save the class. Confirm both linked instances update in configuration. Re-add the containing display to Quick Online View and confirm both runtime tiles update while preserving their different tags.
Expected result
One class edit changes both linked instances; their ModuleTag values remain distinct.
DeltaV / Operate connection
GEM classes themselves cannot be published. Changes propagate to linked instances in saved configuration; the containing displays must be tested/refreshed and eventually published.

Phase 09

Connect read-only module data and an animation

This phase needs real module/parameter paths. The example AI1/PV.CV suffix is only valid if that block and parameter exist in the chosen modules. Do not create or download controller logic just to make an example string resolve.

DeltaV Explorer / Control Studio

Open DeltaV Explorer using Windows Start. Locate the chosen Tag A module and open it in Control Studio for inspection using the site’s normal workflow. Identify a parameter suitable for read-only display, its data type, and the exact block/parameter/field path. Use that verified path in the next step. For Tag B, confirm whether the same relative suffix exists. Make no logic edits, downloads or value changes.
Expected result
You have an actual readable path instead of a guessed pump status name.
DeltaV / Operate connection
Control Studio shows control-module logic and parameters. A GEM does not define those controller parameters; it references the interface that the module already exposes.

Graphics Studio → TRAIN_PUMP_POPUP

Add a Data Link from the Palette. In Basics → Data Source, set Type to match the selected parameter. Use the expression/parameter browser to select its actual absolute path. For example, a Numeric link might use DLSYS["TRAIN_P101/AI1/PV.CV"] only when that exact parameter exists. Set Writes → Not allowed. Choose readable decimal places and save.
Expected result
The popup has a read-only data link bound to one known parameter.
DeltaV / Operate connection
The data link is the runtime connection between the HMI and a DeltaV parameter. Its expression selects the source; the element controls how the result appears.

Graphics Studio / Quick Online View

Verify and refresh the popup in Quick Online View. Open it and compare its value and quality/status with the known source. If the value is invalid, investigate the module name, block/field, data type, connectivity and permissions. Do not substitute a fabricated zero for a failed read.
Expected result
The displayed value is demonstrably associated with the intended parameter.
DeltaV / Operate connection
An invalid parameter connection is separate from a popup-opening problem. Proving one absolute path keeps those problems distinguishable.

Graphics Studio → Data Link → Expression

If Tag A and Tag B expose the same relative path, replace the literal module name with Dsp.Tag. For the illustrated AI example the expression is DLSYS[Dsp.Tag + "/AI1/PV.CV"]. Replace the suffix with the verified one. Save, verify, requeue and open the popup from both tags. If their structures differ, use a compatible pair or explicitly map the different paths; a shared popup cannot assume identical block structures.
Expected result
The same data link reads Tag A when opened from A and Tag B when opened from B.
DeltaV / Operate connection
This completes the chain: instance ModuleTag → click action Tag → popup Dsp.Tag → parameter expression → controller value.

Graphics Studio → popup Rectangle → Basics

Add a rectangle next to the data link. Choose its Visibility property diamond, then the simple Animation / Animate option shown by your release. In the condition/value expression, use the verified numeric data expression compared with a chosen demonstration threshold, for example DLSYS[Dsp.Tag + "/AI1/PV.CV"] > 50 only for the matching AI example. Set the fallback/default to hidden/false as offered. Add a label explaining the condition; verify and refresh the test.
Expected result
The rectangle is visible when the expression resolves true and hidden when false. If the signal never crosses the threshold, only one animation state has been demonstrated.
DeltaV / Operate connection
The graphic property follows a configured expression. This is an HMI animation, not an added control-module scan or a custom looping script. Exercise both states only with an approved test signal/environment.

Phase 10

Understand publication and finish the exercise

Publication is a separate deployment activity. Complete the learning exercise in Quick Online View first. Only perform the optional publication steps on the intended approved training destination; leave them unchecked otherwise.

This checklist / Quick Online View

Check that you observed: two tags reaching one popup; the detail receiving the same context; two GEM instances preserving different ModuleTag values; a class change updating both linked instances; a real data value; and both animation states. Leave untested steps unchecked. A checked box should mean the result was observed, not just that the instruction was read.
Expected result
You can distinguish completed behavior from assumptions and untested behavior.
DeltaV / Operate connection
Configuration validity, runtime behavior, controller data quality and deployment are separate evidence checks.

DeltaV Live Administration / site administrator

For normal runtime, the workstation/session needs appropriate Live configuration, including its assigned layout and display sets/navigation as applicable. Use the existing training workstation setup. If it is not configured, have the site administrator establish it under the installed release’s workstation procedure. Do not switch the active graphics database as a shortcut.
Expected result
The intended runtime destination is known and configured before publishing.
DeltaV / Operate connection
A layout arranges runtime screen regions; a display set groups displays and navigation. Neither is the process display itself. Live Administration manages workstation/session assignments.

Graphics Studio → Home → Publish

After verification and the site’s required review, select TRAIN_CONNECTIONS, TRAIN_PUMP_POPUP and TRAIN_PUMP_DETAIL in Graphics Explorer, using Ctrl for multiple selections. Choose Home → Graphics → Publish. In the dialog open Choose Destinations, select only the intended training workstation(s), and inspect the item list before clicking Publish. Do not choose Publish All Pending. Targeted publishing applies to displays/contextual displays; prior targeted destinations can constrain later choices.
Expected result
The specified exercise displays are published to the selected allowed destinations.
DeltaV / Operate connection
This replaces the deployment role of copying graphics files in an Operate workflow. Class changes reach runtime through the containing published displays, not by copying a GEM class file to a station.

DeltaV Live on the intended training workstation

Launch the installed DeltaV Live application from Windows Start or the site shortcut. Open TRAIN_CONNECTIONS through the station’s available display search/navigation. Confirm it is the newly published version; use the applicable refresh prompt/action for cached content. Repeat the context and read-only data checks. If the display cannot be found, check publication destination and runtime display-set/navigation configuration rather than changing controller logic.
Expected result
The behavior is confirmed in normal runtime on the intended workstation, separately from Quick Online View.
DeltaV / Operate connection
Published configuration and an already-loaded display can differ until refreshed. Runtime validation establishes what the operator station actually loads.

This checklist

Review the mapping: Operate runtime UserForm → contextual display and controls; dynamo configuration options → GEM Configuration Designer; bulk graphics-editing Configure form → a separate engineering workflow, not this runtime popup.
Expected result
You can explain where each responsibility belongs.
DeltaV / Operate connection
This exercise implements a runtime GUI pattern. Python/XML engineering tools, rich tree widgets, arbitrary package imports and bulk graphics migration require their own separate design and validation.
