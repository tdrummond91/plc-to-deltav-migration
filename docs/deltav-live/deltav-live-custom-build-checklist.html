Three practical build patterns

Make it. Connect it. Inspect it.

A short build order with expandable instructions. Work through the example you need, then use the shared finish checklist. Checkboxes record your progress; they do not run anything in DeltaV.

Custom build, not automatic code generation. These examples assemble and configure Live objects in Graphics Studio. They cover common popup, GEM, faceplate and diagnostic patterns—not every control or a native VBA UserForm converter. Menu names/capabilities should be checked against your installed v14/v15/v16 help.

  • How · component connection · help

Use a test configuration and read-only/sample data for these exercises. These instructions do not require changing a controller module.

  • How · component connection · help

    Help: The Graphics Studio user interface · The Graphics Studio ribbon
  • How · component connection · help

    Help: Create a configuration library

    You can start with a blank document and plain elements. Create a GEM class only when you need a reusable component. You do not need to create a separate Palette: available classes/elements are exposed through the existing Palette. Optional Layout/DisplaySet work comes after the graphics exist.

Example 01 · Button → contextual display → data / appearance

Custom information window

0 complete

Operate: header button → popup .grf or simple runtime UserForm.

1. Create the two documentsGraphics Explorer0/2
  • How · component connection · help

    Graphics Explorer → Home → New → Display → Blank Display. Rename it DEMO_MAIN. Set dimensions/appearance in Graphics Configuration and save.

    Help: Create a display
  • How · component connection · help

    Graphics Explorer → Home → New → Contextual Display → Blank Contextual Display. Rename it DEMO_INFO. This is the custom window; it has a separate saved definition from DEMO_MAIN.

    Help: Create a contextual display · Contextual displays overview
2. Add content and resolve reusePalette → document0/2
  • How · component connection · help

    On DEMO_INFO, place suitable text/data-link elements. On DEMO_MAIN, place a button labeled Open information. Use Graphics Configuration for labels/appearance and Selection to confirm ownership. A simple window does not need a custom GEM.

    Help: The Graphics Studio user interface · Create a display · Create a contextual display
  • How · component connection · help

    Reuse a suitable custom GEM through the Palette. If none exists, follow Example 2’s class/property steps, save the class, return to the document and place an instance. The class is the definition; the placed GEM is the instance.

    Help: Create a GEM class from scratch · GEMs (linked and unlinked)
3. Give the window data and consistent stylingStandards / properties0/2
  • How · component connection · help

    Use the property browser/diamond to select a compatible source; verify the actual expression generated by the editor. Start with one known value before generalizing it to a module/context-based reference. Do not guess a production parameter path.

    Help: GEM configuration property types · Contextual displays overview
  • How · component connection · help

    Library Explorer → Standards → Home/New to create a missing shared value. Use the property’s diamond → Browse for Standard. For input-dependent color/font, choose a compatible Library Animation referencing a function instead. Shared static values and conversions are different dependencies.

    Help: Create a standard · Standards overview · Library functions overview
4. Connect the opener to the windowButton interaction0/2
  • How · component connection · help

    Select the button on DEMO_MAIN, open its Interaction tab, add a Click Action, select Open Contextual Display and select DEMO_INFO. Set the tag/context required by your popup. This built-in behavior is sufficient; custom TypeScript is optional.

    Help: Button: Configurable properties (Interaction tab) · OpenContextDisplayAsync function
  • How · component connection · help

    If the popup is intended for several modules, configure its references to use the opening context through the installed editor/help. Test with two different known test contexts and check that the displayed value changes accordingly.

    Help: Contextual displays overview · OpenContextDisplayAsync function
5. Create one small script to inspect in the exportOptional teaching exercise0/2
  • How · component connection · help

    For the export exercise, add a second button on DEMO_MAIN with Click Action → Custom Script. Open its Edit Script / Script Assistant and enter: const demoMarker: string = "DEMO_BUILD_MARKER"; This harmless local declaration intentionally has no visible effect. The first button still opens the window. Verify the script in the installed editor.

    Help: Button: Configurable properties (Interaction tab) · The Script Assistant
  • How · component connection · help

    Script Assistant edits existing scripts; it does not create actions/animations/events. Create the owner/action in Graphics Configuration first. Notice the script’s owning object and event so the exported text can later be traced back to the UI.

    Help: The Script Assistant
6. Verify and exercise the opening pathQuick Online View0/2
  • How · component connection · help

    Select each item or activate its document tab, then Home → Graphics → Verify. Fix errors using Verification Results → Open Item. Saving and verification do not publish the window to operator runtime.

    Help: Verify the configuration in a graphics configuration
  • How · component connection · help

    A Display, DisplaySet or Layout must be active to add it to the queue. Test the contextual display through the calling main display. Re-add changed configurations after edits. Test open, close and reopen, valid/missing context, labels and fallback appearance.

    Help: Test a display, display set, or layout online prior to publishing · Testing graphics configuration online prior to publishing

Example 02 · Class → options → two instances → contextual faceplate

Reusable GEM + custom faceplate

0 complete

Operate: source dynamo + configuration dialog → placed dynamos + faceplate picture.

1. Create or reuse the classLibrary Explorer → GEM Classes0/2
  • How · component connection · help

    Select GEM Classes in your custom library → Home → New → GEM Class. Rename it GEM_DemoStatus. Add a simple status symbol and label from the Palette. An alternative is creating a class from an existing display element; use the documented workflow for that route.

    Help: Create a GEM class from scratch · Create a GEM class from a display element
  • How · component connection · help

    Use Selection to inspect the tree. Group local pieces if useful. Place a nested GEM instance only when you need another reusable definition. Nesting is composition, not GEM-class inheritance. Save the class.

    Help: GEM classes overview · Working with groups · GEMs (linked and unlinked)
2. Expose useful configuration optionsGEM Configuration Designer0/2
  • How · component connection · help

    In the GEM Configuration Designer, Add Property Group, select it, then Add Property → desired type. Suggested example options: Module (Control tag), Label (Multi-language string), ShowLabel (Boolean), and optional Status (Parameter reference). These names are yours, not built-in universal GEM members.

    Help: Add a GEM configuration property to a GEM class · GEM configuration property types · GEM Configuration Designer
  • How · component connection · help

    Give each option a useful title, description and tooltip. Set class defaults in Value. Presence controls whether an option is offered in configuration; it is not runtime visibility. Select the child property’s diamond → GEM Configuration Properties to reference the option. Preview shows the form but changes made only in Preview do not persist.

    Help: Add a GEM configuration property to a GEM class · GEM Configuration Designer · GEM configuration property types
3. Add typed appearance and class behaviorStandard / library function / interaction0/2
  • How · component connection · help

    Library Explorer → Functions → Home/New → Color function (use the equivalent installed menu label). Configure named inputs, optional calculations and Rule-Based / Value-Based / Script conversion. Return compatible colors, using shared Standards when appropriate. Use the child color property’s Library Animation to reference it.

    Help: Create a function · Library functions overview · Function: Configurable properties (Basics tab)
  • How · component connection · help

    Use generated/browsed expressions for your actual option names rather than assuming a universal ModuleName property. ShowLabel can drive an eligible Boolean/visibility expression. If a source is missing or bad, define the desired fallback state. Edit shared interactions on the class.

    Help: GEM configuration property types · Using animation to customize displays · GEM class: Configurable properties (Interaction tab)
4. Build the custom contextual faceplateGraphics Explorer0/2
  • How · component connection · help

    Graphics Explorer → Home/New → Contextual Display. Choose a suitable custom/template starting point or Blank. Add compatible data links, labels and GEM content. Keep this exercise read-only; adding controller writes is a separate validated behavior.

    Help: Create a contextual display · Contextual displays overview · Templates overview
  • How · component connection · help

    For an explicitly named custom faceplate, use Open Contextual Display targeting FP_DemoStatus and pass the tag/context. Open Faceplate is a different route: it uses the tag’s configured faceplate association. Test that route only after configuring/confirming the association using the installed system’s help.

    Help: OpenContextDisplayAsync function · OpenFaceplateAsync function · GEM class: Configurable properties (Interaction tab)
5. Place two instances and compare behaviorDisplay + Palette0/2
  • How · component connection · help

    Save the class, return to DEMO_MAIN, find the class in the active Palette and place two instances. Set different test tags/labels through the exposed options. Confirm they track the intended class and each opens the right context.

    Help: The Graphics Studio user interface · GEMs (linked and unlinked)
  • How · component connection · help

    Change a shared label style on the class and observe both linked instances. Try one eligible property override only if the exercise needs it. Remove the override to restore tracking. Adding/removing instance children requires class editing or deliberate unlinking; do not unlink just to change an exposed option.

    Help: Using overrides to modify linked GEMs · GEMs (linked and unlinked) · Add a display element to an unlinked GEM
6. Validate reuse and the faceplate lifecycleVerify → Quick Online View0/2
  • How · component connection · help

    Check property types, missing references, fallback values and each instance’s values. Changing a class is not the same as publishing the containing graphics.

    Help: Verify the configuration in a graphics configuration · GEM classes overview
  • How · component connection · help

    Open both contexts, close/reopen, and check that one instance’s configuration does not leak into the other. Test the shared function with representative input states and invalid/missing data. Follow the shared export finish below.

    Help: Test a display, display set, or layout online prior to publishing · Testing graphics configuration online prior to publishing

Example 03 · Contextual display → tabs/table → selection → scripts

Diagnostic window + lifecycle

0 complete

Operate: runtime UserForm with controls and event handlers. This is a redesigned supported UI, not an automatic TreeView conversion.

1. Create the diagnostic document and openerContextual display0/2
  • How · component connection · help

    Create a blank/template contextual display, then a main-display button with Open Contextual Display. Give the diagnostic UI explicit context if it will inspect different modules. Reuse the same opening pattern from Example 1.

    Help: Create a contextual display · Button: Configurable properties (Interaction tab) · Contextual displays overview
  • How · component connection · help

    Use the active Palette and each element’s properties. Configure tab items, labels and selection/visibility behavior using the installed editor. Do not assume a tab item is a generic container for arbitrary graphics; check the actual tab/control model.

    Help: Configuring a tab · Tab item: Configurable properties (Basics tab) · Configuring a table
2. Start with a small table before dynamic dataTable configuration0/2
  • How · component connection · help

    Use the Display static data in a table topic to set up a few representative rows/columns first. Confirm field names and rendering before using live or SQL data. SQL connectivity and permissions are a separate setup; this example does not require them.

    Help: Display static data in a table · Configuring a table
  • How · component connection · help

    Set the table’s Primary Key Field and confirm uniqueness. Duplicate keys can cause multiple rows to appear selected together. Then choose single/multiple selection, row/column selection, sorting/filtering or paging as needed.

    Help: Configuring a table · Configuring table selection through scripting
3. Connect selection to useful behaviorTable / button handlers0/2
  • How · component connection · help

    Create the desired event/action first, then use Script Assistant to insert the actual named table reference and documented GetSelectedItems or GetSelectedValues call. Check the selected data before deciding what context to open. Do not copy placeholder Table names without adapting them to the actual element.

    Help: Configuring table selection through scripting · The Script Assistant
  • How · component connection · help

    Select the owning contextual display/group/GEM and use its Variables tab. Choose a compatible type. Reference-backed variables can be read-only online. Keep temporary UI state separate from controller values and shared Standards.

    Help: Variables overview
4. Define initialization and optional refreshContextual display Interaction tab0/2
  • How · component connection · help

    Configure the contextual display’s Interaction events as needed: OnOpen, OnClose, OnActivated, OnDeactivated, OnMinimize, OnRestore. Repeated activation is not the same as first opening; avoid accidentally duplicating initialization or accumulating state.

    Help: Contextual display: Configurable properties (Interaction tab)
  • How · component connection · help

    If no refresh is needed, leave out the timer and mark this decision complete. A configured timer executes while its owner is open and Active is True; after re-enabling, a full duration passes before execution. Test disable/re-enable and close/reopen. Do not add polling when ordinary data bindings already do the job.

    Help: Contextual display: Configurable properties (Interaction tab)
5. Review scripts and error behaviorScript Assistant0/2
  • How · component connection · help

    Identify each script’s owner and trigger. Verify syntax/references with Script Assistant. Use installed documentation for asynchronous APIs and exceptions; a popup-opening promise is not proof that all process data has loaded.

    Help: The Script Assistant · OpenContextDisplayAsync function
  • How · component connection · help

    Handle missing selection, empty data and failed lookups. For any message boxes, the scripting tips advise invoking them from a contextual display so they do not hide behind popups. Keep a clear fallback view rather than leaving stale values unexplained.

    Help: Scripting tips for DeltaV Live
6. Exercise the whole window, not only its first openingVerify → Quick Online View0/2
  • How · component connection · help

    Use Home → Verify on the changed configurations. Launch through DEMO_MAIN in Quick Online View. Confirm labels, fields and context before adding more complexity.

    Help: Verify the configuration in a graphics configuration · Test a display, display set, or layout online prior to publishing
  • How · component connection · help

    A table/tab redesign does not automatically provide an expandable TreeView. If hierarchical browsing is still required, treat that as a separate version-specific prototype. Follow the shared export finish below to inspect how this configuration and its scripts are represented.

    Help: Configuring a table · Contextual display: Configurable properties (Interaction tab) · Testing graphics configuration online prior to publishing

Inspect scripts, export, then verify portability

0 complete

Native export = XML .ahc configuration. Standalone .ts files are a separate review extraction. Keep the source configuration and script ownership together.

  • How · component connection · help

    Export uses the last saved version. Exported files of the same name overwrite existing files in the selected folder, so choose a new local review folder for this exercise.

    Help: Exporting graphics configuration overview
  • How · component connection · help

    Select DEMO_MAIN and the relevant custom contextual displays/classes, or the chosen custom folder. Include dependent items brings linked GEM class dependencies with the graphic. Inspect the selection/results so the expected Standards/functions and other dependencies are present. Leave unmodified out-of-the-box items excluded unless you specifically need them.

    Help: Export a graphics configuration · Export pane reference
  • How · component connection · help

    Leave Compress into zipped folder off for this first review, then Export and check each result. Optional metadata creates ExportMetadata.log. A .ahc file is XML configuration exchange content; this is not a native export of separate TypeScript project files.

    Help: Exporting graphics configuration overview · Export a graphics configuration · Export pane reference
  • How · component connection · help

    Look for DEMO_BUILD_MARKER from Example 1 or a distinctive string from one of your scripts. Inspect the surrounding XML to see the actual script representation in your release. The supplied help documents XML export but does not establish a fixed script-node schema. If your expected code is absent, verify the saved owner, export selection and dependencies rather than guessing a schema.

    Help: Exporting graphics configuration overview · The Script Assistant
  • How · component connection · help

    This is a manual extraction/review artifact, not a documented native .ts export. XML text may need entity/CDATA decoding if extracting it programmatically. Keep each fragment’s owner, event/property and source .ahc filename beside it. Do not invent wrapper classes or treat the fragments as a standalone Node/browser program.

    Help: The Script Assistant · Exporting graphics configuration overview
  • How · component connection · help

    Select only the custom .ahc items you intend to import. Resolve conflicts deliberately, then Verify and test the calling display. A successful export alone does not establish compatibility between v14/v15/v16 or validate runtime behavior.

    Help: Import graphics into Graphics Studio · Verify the configuration in a graphics configuration
  • How · component connection · help

    Create/choose a Layout with Screen/DisplayFrame routing, and a DisplaySet containing the intended Display references. Assign through Workstation Management on the intended test station/session. A custom popup opened by a button does not itself require a new workstation layout.

    Help: Layouts overview · Display sets overview
  • How · component connection · help

    Publish the eligible changed configuration and dependencies as appropriate to the installed system. A GEM class is not itself published; its containing displays deploy its graphical changes. Standards/functions have their own publication lifecycle. File export/copy is not equivalent to publishing Live configuration.

    Help: GEM classes overview · Standards overview · Library functions overview · Layouts overview
