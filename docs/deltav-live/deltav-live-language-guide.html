Language choices in DeltaV Live

The operator chooses an active content language. Engineers supply the translations, defaults, fallback and available language choices.

This guide covers configurable graphic content. It does not establish automatic translation of arbitrary script strings, controller descriptions, third-party controls, Windows, or the complete DeltaV application interface. Check each text source.

1 · What the operator clicks

  1. In the running DeltaV Live application, open Tools → Languages and choose the desired active language. The supplied help identifies this menu; its availability also depends on privileges and the installed layout/release.
  2. Check the process display and its contextual popups. Localized properties use the configured translation for that language, or the configured fallback if their translation is missing.
  3. On a later launch, the application uses the language last used by that DeltaV user, in that application, on that workstation/session. A new user/session combination, or an inactive previous choice, uses the system default.

A user’s preference is not documented here as a plant-wide roaming preference. Do not assume changing one console changes every other console.

2 · Choices that determine the result

ChoiceWhat it controls
Active languagesLanguages available for content selection. Added but inactive languages are not operator choices.
Language Name / TitleName identifies the language in Graphics Studio and import matching; Title identifies it in Live. Use clear operator-facing titles.
System defaultThe starting content language when no valid remembered user preference exists.
FallbackThe language used for a missing translated string. This differs from the initial/default language. Without fallback, missing strings can be blank.
Decimal SymbolThe decimal separator used to represent floating-point values for the selected content language. Include numeric displays in acceptance testing.
LicenseThe supplied help documents at most two active content languages without the Premium entitlement, and up to eight with it. Confirm the installed v14/v15/v16 entitlement; this is not a newly verified commercial licensing statement.
PrivilegesThe help requires appropriate privileges to switch languages. It does not identify the exact security key in these topics; confirm that assignment in the installed system’s security help.

3 · Engineer setup, step by step

  1. Open Graphics Studio → Library Explorer. Double-click Languages.
  2. Choose New Language if needed. Set Name, Title, Description and Decimal Symbol. Activate the languages operators should be able to choose.
  3. Set FALLBACK LANGUAGE and SYSTEM DEFAULT LANGUAGE deliberately. A default does not fill missing translations; fallback does.
  4. Open the graphic to translate. Select View → Views group → Translation Guide. Edit the relevant language columns for each element/property; press Enter and save. A newly activated language may require closing and reopening Translation Guide.
  5. Alternatively, click a localizable property field in Graphics Configuration and use its language selector to inspect/edit a particular language. The fr selector in your screenshot is an authoring-language selection for that property—not an operator language switch.
  6. Use the Graphics Studio menu bar’s Application Preferences language choice to inspect all configurable content in another language. This is the authoring application's selection.
  7. Save and publish Languages: with its tab active, Home → Graphics group → Publish → Publish. Languages publish as a group.
  8. Also save and publish the graphics configuration or shared content you translated, using its applicable publication workflow. Publishing Languages deploys language definitions/settings; it does not publish the associated translated strings on graphics.

4 · How it connects to the UML

Language configuration provides the active language/default/fallback context. A localizable Display/GraphicElement property supplies translated text for that context. A reusable Multi-language String Standard supplies shared localized text where the property accepts it. This is value selection; it does not instantiate a separate Display for every language.

Open Standard and Display in the class inspector →

Keep technical identifiers and user-facing text distinct. A fixed string returned by a custom script is not proven multilingual merely because the selected content language changes. Prefer documented localizable properties/shared multilingual values for operator labels, and prototype custom string sources explicitly.

5 · Make sure it matches the operators’ needs

Suggested acceptance checks, to perform with a representative operator account on each intended workstation/session:

  1. Choose each allowed language from Tools → Languages; confirm the expected choices appear under the actual account/license.
  2. Review main displays, GEM labels, faceplates, details, popup titles, buttons, tooltips and diagnostic tables. Trace fixed script/database/controller strings separately instead of assuming they translate.
  3. Review longer translations for clipping/wrapping, correct fonts/glyphs, terms operators recognize and decimal separators. Have a fluent operator review the actual displayed wording.
  4. On a test item, leave one translation missing and confirm the intended fallback. The help suggests temporarily leaving fallback unspecified during configuration to expose omissions, then setting a fallback before production publication.
  5. Close and relaunch Live with the same user/session; verify the remembered choice. Repeat with a first-use user/session to verify the default.
  6. After publishing, inspect the target workstation. Confirm both the language definitions and changed graphic content arrived; test one changed label rather than relying only on publication success.

If the chosen language does not appear or text stays unchanged
  • Check Active status, publication, privileges and license limits. Without Premium, the help says the runtime list can be reduced to two choices, prioritizing default and fallback.
  • Check whether the property is genuinely localizable, whether a translation exists, and whether you published its owner.
  • Check whether a fixed literal/script/data-source string is supplying that label. Translation Guide does not establish automatic translation for every external data source.
  • Check whether a missing translation is silently falling back to another language.
