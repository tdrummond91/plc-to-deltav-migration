Ownership. Reuse. Execution.

UML class and object models, activity flows, and runtime sequences. Follow one relationship at a time: what owns an item, what refers to a shared definition, and what executes when an event occurs.

Start with containment ↓

How to read these models

These are conceptual UML models of documented behavior, not a dump of Emerson’s internal classes or an SDK. Names such as GraphicElement and PropertyValue express concepts; they are not asserted programming identifiers. Each diagram states whether it is a type model, an example object model, or an execution flow.

03 / EXPOSED OPTIONS & THEIR EFFECTS

Which options does an object expose, and what uses them?

A configuration contract means the interface offered to whoever configures the object: option names, types, defaults, constraints and intended effects. It is an explanatory term here, not a separate DeltaV component.

For example, a Boolean option named EUVisibility is useful only if the units label’s Visible property consumes it. In Live, trace definition → instance value → consuming child property. In Operate Configure, trace form control → VBA handler → changed graphic objects. The worked example supplies the objects; this section explains how their options affect their children.

04 / DATA-TO-VISUAL EVALUATION

How does data become a displayed result?

The evaluation flow traces a value through its expression, animation or function into a graphic property. Example: a pump-status value is converted to a color, and that color is used by the pump symbol’s fill. Use it to locate the data source, the conversion rule, the consumer and any fallback when data cannot be resolved.

A function returns a value; the property consumes it. This does not require an operator click. A runtime event sequence instead follows a trigger and the actions it causes. The exposed option may supply an input to either path.

05 / SEQUENCE DIAGRAMS

What happens after a click?

The object owns the trigger; the handler requests another UI; the popup receives context and uses it to resolve data. That call chain is not the same thing as graphic containment.

06 / ASSOCIATION MODEL

Which hierarchy controls the screen?

There are three independent structures: the object tree inside a graphic, the layout’s screen-space tree, and the display set’s navigation hierarchy. Do not merge them into one tree.

ConfigurationLibrary

Repository for reusable definitions. Library Explorer is the authoring view, not a second runtime owner.

What can be created or contained?

Create GEM classes, templates, standards, functions and organizational folders. Languages/themes are also managed in Library Explorer, separately from the four library-item families.

Limits & distinctions

Definitions are referenced or used as creation sources; placing a graphic does not duplicate this whole repository.

Attributes

+ name : String

Identifier for this configuration item or model object. Naming scopes differ: library item names are local to their configuration library.

+ items : LibraryItem [0..*]

Reusable library definitions: GEM classes, templates, standards and library functions. These are definitions, not placed screen objects.

+ folders : Folder [0..*]

Organization in the Explorer tree. A folder is not another value type or a graphic instance.

Operations · conceptual responsibilities

+ organize(item : LibraryItem)

Organize library definitions into folders through the authoring UI.

+ find(name : String) : LibraryItem

Locate a named reusable definition. This describes the lookup responsibility; it is not a callable find API.

GraphicDocument

A conceptual common category for saved graphical documents, not a concrete item named GraphicDocument in the UI.

What can be created or contained?

Create a Display or Contextual Display. Add supported elements, groups and GEM instances to the chosen document; variables and interactions are configured on the owner.

Do not instantiate the abstract category itself. The active Palette determines what is available.

Identifier for this configuration item or model object. Naming scopes differ: library item names are local to their configuration library.

Graphic content owned by this document. Groups and GEMs can introduce additional levels of containment.

+ variables : Variable [0..*]

Scoped values or references available to expressions and scripts. A variable is not itself a visible graphic.

Operations · conceptual responsibilities

Persist authoring changes. Saving and publishing/deploying are separate actions.

Deploy publishable configuration changes to Live. This is an editor/deployment responsibility, not a method on an SDK class.

Open the configured document at runtime, optionally with context. Real API selection and arguments are covered in Section 5.

ContextualDisplay

A context-dependent popup definition reused with different tags/modules.

What can be created or contained?

Can contain supported graphics, GEM instances, variables and actions. Faceplates, details and Batch controls are documented examples of contextual displays.

Limits & distinctions

The opening action passes context; opening the popup does not make it a child graphic of the clicked button.

Attributes

+ name : String

Identifier for this configuration item or model object. Naming scopes differ: library item names are local to their configuration library.

+ context : Context

The tag/module and any additional context used when opening this UI. Context selects data; it does not copy the popup definition.

+ kind : Faceplate | Detail | Custom

The role or configuration family of the item, rather than an asserted native subclass enumeration.

Operations · conceptual responsibilities

+ initialize(context : Context)

Apply the incoming context and establish the UI’s initial state. Actual initialization events and code vary.

+ activate()

Bring an open UI into its active state; distinguish activation from initial creation/opening.

+ close()

Close the runtime document/UI. Closing does not delete its saved definition.

GEMClass

Reusable graphical definition tracked by linked GEM instances.

What can be created or contained?

Define child elements, groups, nested GEM instances, custom properties/property groups, variables and interactions. Place instances of this class on eligible configurations.

Limits & distinctions

Edit the GEM class’s contained graphical elements and nested reusable instances.

Configure the class’s event behaviors. Linked-instance interactions are edited on the class.

Save the GEM class definition. A class itself is not published; containing displays are deployed through their publication lifecycle.

GraphicElement

Abstract category for a placed graphical object. Individual kinds have different properties and legal owners.

What can be created or contained?

Examples in the supplied help include shapes, text, images, data links, buttons, radio buttons, tables, tabs and alarm/Batch controls; groups and GEM instances provide composition. Text can own data placeholders; tabs own tab items.

Limits & distinctions

This is not a universal placement matrix. The active document’s Palette and each control’s help decide what can be placed there.

Attributes

+ name : String

Identifier for this configuration item or model object. Naming scopes differ: library item names are local to their configuration library.

+ geometry : Geometry

Position, size and applicable transformation values. Supported geometry properties depend on the element type.

+ bindings : Binding [0..*]

The data references, expressions or animations that supply this graphic’s property values. Binding is an explanatory category.

Operations · conceptual responsibilities

+ evaluateAppearance()

Resolve data/expressions into visible property values. This is evaluation, not a click-event sequence.

+ dispatch(event : Event)

Route an event to the configured behavior, where supported by the element.

+ render()

Present the resolved graphical appearance. This models a runtime responsibility, not a user-callable render function.

Interaction

A configured trigger and behavior attached to an eligible owner.

What can be created or contained?

Configure supported triggers and actions: custom script, writes, opening displays/contextual displays/faceplates/details, and other owner-specific actions. Document owners can also have lifecycle events and timers.

Limits & distinctions

Trigger availability varies. A timer belongs to configuration, not to a library function just because both execute code.

Attributes

+ trigger : EventKind

The configured occurrence that invokes a behavior, such as click or hover. Available triggers depend on the owning element.

+ action : ActionDefinition

The selected behavior and its configuration: for example, a popup request, a write action or a custom script.

+ owner : GraphicElement

The element associated with the behavior in this model. It is not a claim about an internal runtime object pointer.

Operations · conceptual responsibilities

+ handle(event : Event)

Execute the behavior/procedure associated with an event. Actual trigger and handler signatures depend on the owner.

+ resolveContext() : Context

Determine the tag/module and additional values to pass to the requested UI.

+ requestPopup(context : Context)

Ask runtime to open the configured popup with context. In Operate the target may be a picture or a separate UserForm.

GEMInstance

A placed GEM, either linked to a class or unlinked.

What can be created or contained?

Linked: instance options and eligible overrides. Unlinked: add an existing GEM instance, group or single display element; customize its own property schema. Nested links can remain.

Limits & distinctions

Do not add/remove child structure on a linked instance as if it were an ordinary unlinked container. Edit the class or intentionally unlink.

Attributes

+ classRef : GEMClass [0..1]

The shared GEM class tracked by a linked instance. An unlinked GEM has no outer class reference; nested instances can still be linked.

+ linked : Boolean

Whether this placement tracks a GEM class. Being linked restricts structural edits and changes the rules for overrides.

+ values : OptionValue [0..*]

The instance’s configured values for exposed GEM options. The class defines what options exist; each placement supplies values.

Operations · conceptual responsibilities

+ setOption(name : String, value : Any)

Assign a value to an exposed instance option, using the option’s allowed type and configuration rules.

+ overrideEligibleProperty()

Override an eligible nested property on a linked GEM. This does not allow adding/removing child elements or changing nested animations.

+ unlink()

Remove the outer instance’s GEM-class link. Nested GEM links may remain.

Group

Local composition of one or more graphical elements.

What can be created or contained?

Group members can be graphical elements, including existing groups/GEM content as supported by the editor. Groups can have scoped variables and supported behavior.

Limits & distinctions

A Group has no GEM Configuration Designer or GEM class link. Grouping and reusable class creation solve different problems.

Attributes

The graphic elements grouped together. The group owns this local collection; grouping does not create a shared GEM class.

+ variables : Variable [0..*]

Scoped values or references available to expressions and scripts. A variable is not itself a visible graphic.

Identifier for this configuration item or model object. Naming scopes differ: library item names are local to their configuration library.

Operations · conceptual responsibilities

+ add(element : GraphicElement)

Add an eligible graphic to the local container using the authoring workflow. This is not unrestricted runtime object creation.

+ remove(element : GraphicElement)

Remove a member from this container in the model. The actual editor command determines whether it is deleted, moved or ungrouped.

+ transform(geometry : Geometry)

Apply position/size/transformation changes to the container and its members according to editor behavior.

OptionValue

A configured value for one exposed option on a GEM placement.

What can be created or contained?

Assign a compatible literal, reference, animation or expression where that option type permits it. This value is not a container for more graphic objects.

Limits & distinctions

A Display reference excludes contextual displays. Parameter/Scale references have specialized rules; many option types are not animate-able.

Attributes

+ definition : OptionDefinition

The option schema this value conforms to. The reference connects a value to its name, type and configuration metadata.

+ value : Any

The current or configured data carried by this item. Any is model shorthand here, not an assertion that every property accepts every type.

+ expression : Expression [0..1]

An optional expression supplying the configured value, where that property type supports expressions.

Operations · conceptual responsibilities

+ resolve(context : Context) : Any

Obtain the effective value from the configured expression/reference or variant. The signature shows the relevant context, theme or language.

Relationship scope & platform differences
  • GraphicDocument → GraphicElement: an element has one immediate owner; document and group ownership are alternatives ({xor}). GEM content supplies other valid ownership paths. Popup containment is inherited through the conceptual document category.
  • GEM instance → GEM class: linked instances retain a class reference; an unlinked instance has none. The attribute type describes configuration reuse, not inheritance between GEM classes. Eligible overrides and nested links follow Section 2.
  • Source dynamo → placed dynamo: placement creates graphic content. The dashed arrow does not promise Live-style linked propagation. Inspect the site's update code separately.
  • Options: Live has a defined schema/instance distinction. Operate FormOption and ConfiguredValue are illustrative responsibilities of custom VBA, not a universal native object model. Presence and runtime visibility remain different; see Section 3.
  • Variables and bindings: scopes differ by owner. The event-to-variable dependency means code can use state; it does not mean the event handler owns all variables. assign() on a Live variable is constrained by its source and writability.
  • Template / starter picture: creates initial content for a new document. They do not provide ongoing class inheritance. That cross-band creation dependency is omitted from the drawing to keep its long reference lines readable.
  • Screen routing: Layout owns Screens, Screens own DisplayFrames; DisplaySets reference Displays independently. Display and ContextualDisplay are conceptual GraphicDocument specializations; the long Display-to-GraphicDocument generalization is omitted. Operate picture roles similarly are not asserted native subclasses. See Section 6.
  • UserForms: Operate form events can manipulate graphics or runtime data according to their code. No drop-in Live UserForm or general Configure-time scripting host is implied by the blank slot.
  • Model boundary: supporting value types, editors, controllers, deployment services, ActiveX dependencies, individual leaf controls and every API overload are not expanded. This is a consolidated class view of the reference's graphics scope, not an exhaustive reverse-engineered DeltaV implementation.
